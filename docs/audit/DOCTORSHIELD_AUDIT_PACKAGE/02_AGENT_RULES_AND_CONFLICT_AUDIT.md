## 1. Executive Summary & Root Instruction Diagnosis

The forensic audit of the instruction environment revealed that previous development iterations suffered from **structural instruction conflicts**. Specifically:
1. **The Verbatim Invariant vs. Minimalism Conflict:** An unresolvable tension exists between `AGENTS.md` Rule P-10 / `DEC-002` (requiring 100% verbatim reproduction of all regulatory, legal, and question text) and user prompts demanding extreme minimalism, elimination of explanatory copy, and reduced cognitive load.
2. **The Atomic System vs. Monolithic Route Conflict:** The agent was instructed to design and implement an atomic design system (Atoms in `src/components/ui/`, Molecules in `src/components/form/`, Organisms in `src/components/organisms/`), but subsequent prompts commanded the agent to rebuild the live stages (`Stage1CoverageForm`, `Stage2QuoteReview`, etc.) while preserving all existing test IDs and DOM structures. Consequently, the agent modified the existing monolithic files directly with ad-hoc inline styles, leaving the atomic component library completely orphaned.
3. **Typography Rule Invariant Violations:** `AGENTS.md` Section 4.2 strictly mandates `Kanit` weight 400–500 only (never 600+) and `Inter` weight 400–500. Yet the codebase contains **306 verified instances** of `fontWeight: 600`, `700`, `800`, or `'bold'` in inline styles.
4. **Foreign Rule Contamination:** A global science visualization plugin rule (`C:\Users\salee\.gemini\config\plugins\science\rules\AGENTS.md`) is loaded in the active agent context, attempting to prioritize 3D biomolecular viewers on an insurance transaction repository.

## 5. Rules That Negatively Influence Output Quality

1. **`AGENTS.md` Rule P-10 (Absolute Prohibition on Hiding Content):**
   - *Text:* *"Never remove or hide a required customer-facing question, disclosure, consent checkbox, or link, even if it appears redundant."*
   - *Forensic Assessment:* This prohibition was written as a legal safeguard, but without a clear mechanism for progressive disclosure or collapsible contextual drawers, agents interpreted it as a command to render every single disclosure on-screen simultaneously. This directly caused the visual clutter and "wireframe" density.
2. **`AGENTS.md` Section 3 (Content Preservation):**
   - *Text:* *"All existing customer-facing questions, field labels, help text, options, and choices must be reproduced verbatim..."*
   - *Forensic Assessment:* Prevented any microcopy optimization, resulting in legacy bureaucratic phrasing being preserved verbatim alongside modern minimal UI elements.
3. **Absence of Architecture Enforcement Rule:**
   - `AGENTS.md` contains strict rules on brand colors, fonts, and legal text, but **zero rules mandating component composition**. There was no rule stating: *"Feature screens must be composed from `src/components/ui/`, `src/components/form/`, and `src/components/organisms/` rather than inline JSX."* Consequently, agents generated components to fulfill prompts, but wrote monolithic inline JSX in the actual screens.

## 6. Recommended Rule Categories for Future Clean Configuration

When rebuilding the agent rules in a future phase, the following structure is recommended:

1. **Category 1: Insurance & Underwriting Invariants (Non-Negotiable)**
   - Protect rating formulas, MMC classification mapping, 8% SST, RM 10 stamp duty, and PIDM protection.
2. **Category 2: Controlled Content Optimization (Replacing Rigid Verbatim Rules)**
   - Allow progressive disclosure, modal consolidation, and microcopy refinement while preserving legal intent and required regulatory declarations under formal change logging.
3. **Category 3: Component Architecture Invariants (Mandatory Component Reuse)**
   - Prohibit raw HTML inputs and inline styling in screen features. Mandate composition from approved Design System molecules and organisms.
4. **Category 4: Strict Typographic Enforcement**
   - Programmatically forbid `fontWeight > 500` via linting rules rather than unenforced markdown text.
5. **Category 5: Production Bundle Discipline**
   - Forbid importing development catalogs, test mocks, or demo scrapers into production entry points.
