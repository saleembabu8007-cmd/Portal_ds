# DoctorShield — Visual Design Authority

> **Scope:** Authoritative visual rules governing every customer-facing element, component anatomy, layout composition, typography hierarchy, financial presentation, and interaction design.
> **Version:** 5.0 — Rule 2. Owner: Principal Product Architect & Design Director.

---

## 1. Mission

Own the visual quality of every customer-facing element.

Build a cohesive, distinctive, ultra-minimal insurance interface informed by QIC Online, Wise and the approved user-supplied visual references.

The rejected DoctorShield design system must not be used as the visual benchmark.

---

## 2. Visual personality

DoctorShield should feel:

- **Calm.**
- **Precise.**
- **Premium.**
- **Contemporary.**
- **Trustworthy.**
- **Human-centered.**
- **Visually restrained.**
- **Exceptionally polished.**

Avoid anything resembling generic dashboards, administrative portals, default component libraries or documentation previews.

---

## 3. Reference extraction

### QIC Online
- Clear mobile step navigation.
- Focused single-task screens.
- Carefully composed selection controls.
- Strong but controlled accent colors.
- Premium pricing presentation.
- Refined form spacing.

### Wise
- Financial transparency.
- Clear amount hierarchy.
- Clean input geometry.
- Predictable transaction flow.
- Subtle surfaces.
- Focused action placement.

### Supporting Approved Insurance References
- Readable plan information.
- Clear selected states.
- Compact financial comparisons.
- Deliberate desktop/mobile adaptations.

Do not copy their product offerings, colors, logos or illustrations.

---

## 4. Typography

### Headings
**Kanit**, weights **400** and **500** only.

### Body and Interface
**Inter**.

### Intentional Hierarchy
Define an intentional hierarchy for:
- Page title.
- Section title.
- Group heading.
- Body.
- Field label.
- Input value.
- Supporting text.
- Price amount.
- Final total.
- Action label.
- Legal paragraph.
- Error message.

Do not use tiny text to manufacture minimalism.

Default customer-facing body copy should be comfortably readable, typically around **15–16px** depending on role and contrast.

Avoid multiple competing headings in one section.

Do not use font weight alone as the primary method of establishing hierarchy.

---

## 5. Colors

### Preserved Invariants
- Primary: `#08A5B5`.
- Secondary: `#132766`.

Build accessible interactive variants and a restrained neutral palette.

Use navy for important hierarchy and teal selectively for active states, accents and actions.

Avoid teal borders on every component.

Avoid excessive tinted cards.

Never assume brand teal supports white text at the required contrast.

---

## 6. Composition

Every screen must be designed as a complete visual experience.

Define:
- Content width.
- Form width.
- Page alignment.
- Header structure.
- Section hierarchy.
- Column balance.
- Reading direction.
- Navigation placement.
- Pricing placement.
- CTA placement.
- Mobile transformation.

Use open layout where possible.

Use surfaces only when they create a useful boundary, grouping or selection affordance.

A form field is not automatically a card.

A disclosure is not automatically a card.

A premium summary is not automatically a sidebar.

---

## 7. Component anatomy

Every component must specify:
- Structure.
- Dimensions.
- Content alignment.
- Typography.
- Padding.
- Gaps.
- Border.
- Radius.
- Background.
- Icon size and placement.
- Focus treatment.
- Hover treatment.
- Selected treatment.
- Disabled treatment.
- Error treatment.
- Responsive behavior.

Do not let different screens invent independent versions of the same component.

---

## 8. Borders and radii

Use a compact, consistent geometry system.

Avoid excessive pill-shaped components.

Use thin borders primarily for separation and selection.

Avoid stacking multiple bordered containers.

Use shadows only when required to distinguish an elevated surface or overlay.

---

## 9. Icons

Use one consistent icon family.

Prefer icons for:
- Navigation.
- Editing.
- Actual status feedback.
- Important familiar actions.

Avoid icons beside every label or paragraph.

Use consistent optical alignment and stroke weight.

---

## 10. Financial presentation

All prices must be visually precise.

Use:
- Tabular numerals (`font-variant-numeric: tabular-nums`).
- Clear currency formatting (`RM X,XXX.XX`).
- Appropriate decimal alignment.
- Strong total hierarchy.
- Subtle line-item separation.
- Consistent positive/negative treatments.

Do not use giant decorative price cards.

Do not repeat the same complete breakdown unnecessarily.

---

## 11. Interaction design

Selected states must be obvious without relying on color alone.

Inputs must communicate:
- Default.
- Focus.
- Filled.
- Selected where applicable.
- Invalid.
- Disabled.
- Loading.

Use appropriate keyboard and touch behavior.

Avoid custom interaction patterns when established accessible controls work better.

---

## 12. Responsive composition

Mobile must be intentionally designed.

Do not simply stack desktop columns.

Reconsider:
- Order.
- Width.
- Spacing.
- Selection presentation.
- Pricing access.
- Sticky actions.
- Disclosure placement.

Do not obscure content behind sticky UI.

---

## 13. Visual rejection criteria

Reject a design if it:
- Looks like a slightly styled wireframe.
- Uses the old composition with different colors.
- Repeats too many bordered cards.
- Uses tiny labels.
- Has unclear selected states.
- Displays unnecessary explanations.
- Has inconsistent spacing.
- Has weak alignment.
- Looks disconnected from the approved art direction.

Require identical-state before/after screenshots.

A successful redesign must be clearly distinguishable through layout, component anatomy, hierarchy and composition—not only surface styling.
